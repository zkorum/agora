To settle before rollout

Five design decisions

01 · Existing activities
Preserve effective visibility and participation requirements as explicit overrides when defaults are introduced. Existing Polis conversations remain List.

02 · Ticket within participation
A published activity cannot gain a ticket requirement today. Define how a project participation-default change respects that rule.

03 · Conversation-only Polis
List / Wiki-survey, AI group labels and preferred group count are set on each mapping conversation; none inherits from the project.

04 · Live shared changes
Project edits update inheritors, never overrides. Explain changes to access requirements to active participants; preserve their votes.

05 · My work / my participation
Define what counts as participation, distinguish authored from manageable conversations, and bring authorized project and organization settings into the facilitator workspace.
