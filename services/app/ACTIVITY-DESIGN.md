# Facilitator activity UI: design and API notes

The reference is the **Projects / Mapping**, **Projects / Prioritizing**, and
**Projects / Gathering** sections in Figma (nodes `24019:156791`–`24019:156793`).
Use the working HTML prototype for interaction context where Figma is silent.

In the Svelte app, open an activity draft from its project at
`/project/[projectSlug]/draft/[draftId]`. Unpublished edits are local to the
page. Creating an activity replaces the draft with its validated setup in the
mock project workspace for the current browser tab. Reloading keeps that created
activity; it does not publish a participant URL or write to a server.

The guides share the project authentication help trigger, dialog, dismissal, and
focus return. Their choices never write to the project. Sample suggestions are
not generated by an AI provider. Gathering offers **Gather new responses** and
**Amend existing responses**. The latter requires responses from an earlier
Gathering, so it cannot be created while source selection is deferred. Selecting
it must not publish the draft as a new collection.

Use the activity picker's radio-card appearance for both Gathering formats and
Mapping's **All at once** and **One at a time**. Help examples use informational
cards: they explain the alternatives without changing the facilitator's choice.

Mapping's Help and participant previews use the participant frames **Open —
Add statements enabled** (`24275:129453`) and **One at a time** (`24275:130805`).
Keep statement text inside the card with **Disagree / Unsure / Agree** in a
single row below it. On narrow screens the two Help examples can stack; the
three vote choices stay adjacent. All at once suits asynchronous participation:
people can read what others have said before adding a duplicate. One at a time
suits live events, where participants can focus on the current statement.

In one-at-a-time mode, choosing a response briefly leaves the selected vote
visible. The prototype waits one second, then slides and fades to the next
statement (160 ms exit, 280 ms entrance). The last vote leads to completion
instead of wrapping to the first card. Manual navigation cancels the pending
advance; reduced-motion users get the same progression without the animation.
The list view stays in place after a vote.

**Editing activity details:** Figma’s _Activity settings_ dialog (`24054:12406`)
contains the activity name and description. In the prototype, selecting the
name or description in Setup opens that dialog and focuses the chosen field.
The settings button opens it without a field shortcut. **Save changes** requires
a nonblank name; the description is optional. **Cancel** leaves the Setup
summary and fixed header unchanged. Project and activity summaries share the
same click-to-edit affordance: a highlighted hit area and pencil for a populated
field, or **+ Add description** when it is empty. Read-only activities have no
edit affordance.

**Creation by type:** Mapping keeps its display mode, participant statement
setting and seed statements. Gathering keeps its ordered format, response
visibility, submission setting and seed answers validated against that format.
Prioritizing comparisons keep the pairwise or best–worst method and comparison
items; quadratic voting keeps its opposition setting and titled items with
optional descriptions. Creating a QV activity requires at least one item.

**After creation:** the browser mock represents the facilitator of an activity
with no real participant votes. Mapping and comparison seeds can be added,
edited and deleted; their participant-statement switch remains editable.
With a live adapter, use each seed's edit availability and source version:
participant votes can prevent editing even when deletion is still permitted.
Closing stops participation and is distinct from site moderation locking the
activity. Gathering's field format and visibility are fixed; its submission
switch can change. While closed, a facilitator can delete seed responses but
cannot add or edit them. Prioritizing fixes the method and QV opposition rules;
QV items are editable only while open and before real participation starts.

The Share menu (`24105:142552`) uses **Accepting new responses** to close or
reopen the activity. This is independent of “Allow participants to add new
statements” and the project's directory listing. Local edits and open/closed
changes carry the saved activity revision, so a stale editor cannot overwrite a
newer change. Participant-link actions require a real participant URL.

In the Figma method guide (`24066:130135`), the illustrations under **Pairwise**
and **Best – Worst** are swapped relative to the headings and their descriptions.
Pairwise shows two alternatives and accepts one choice. Best–worst shows a set
and accepts a most- and a least-preferred item. Use each interaction with its
corresponding method.

| Mapping → Moderation → Statement review (`24070:130701`)   | **Moderate** opens one dialog with the statement, a backend reason, optional details and **Move**. | Mapping → Moderation → Approve statements (`24072:131432`) | **Out of scope:** the pre-publication review switch, Awaiting review queue, and Approve / Reject actions are for pre-moderation. They are not requirements for the current UI or API.                                                                                        |
| Linked activities, statements, and responses               | Deferred. Omit source pickers, imports, and linked-source details from the current UI.                                                                                                                                                                                       |
| Gathering → “Short answer” / “Long answer”                 | Short answer starts at **240** characters; Long answer starts at **2,000**. Facilitators can enter a limit directly or override either preset (1–20,000). Only the resulting `characterLimit` belongs in the saved format.                                                   |
| Prioritizing → “requires at least 2 statements”            | Follow the backend rules for the selected method and operation. Do not show or enforce a universal two-statement minimum: QV creation accepts one seed, and comparison creation sets no such minimum on its seed list.                                                       |

Moving excludes a statement from new votes and new analysis inputs. Anyone who can view the activity can still read the statement and its reason in **Moderation History**. It is not deletion or hiding. History retains the origin badge and offers Copy, not a restore action. The demo keeps these decisions across tab switches within the open activity only; leaving or reloading resets them. Seed payloads are not moderation records. Durable integration must use stable opinion IDs, data-backed permissions and backend moderation records. Never send site-moderator-only hidden content to an ordinary facilitator.
